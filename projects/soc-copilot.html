04 / RAG Pipeline

Reuse uploaded evidence across investigation workflows.

One project context, multiple analyst capabilities.

  1. A PDF, TXT, or LOG file is uploaded under a project context.
  2. The data and processing controllers store the asset and split its text into chunks.
  3. Chunks and metadata are persisted in PostgreSQL.
  4. Embeddings are generated and indexed through PGVector.
  5. Search or chat retrieves the most relevant chunks for the selected project.
  6. The selected context is passed to the configured LLM provider.
  7. The system returns a grounded answer or structured security report.

The repository describes the same evidence as reusable across file analysis, AI chat, semantic search, alert triage, investigation, and knowledge-base workflows.

09 / Limitations

An academic prototype, not a hardened SOC product.

Operational boundaries matter in cybersecurity.

  • No production authentication or role-based access control in the public-ready repository.
  • LLM quality depends on model choice, prompt behavior, and available context.
  • External IoC enrichment depends on provider availability and valid API keys.
  • Sigma conversions require review before operational deployment.
  • The Docker Compose setup focuses on PGVector rather than a full production stack.
  • Real incident data must not be committed or shared publicly.
Deployment status

Graduation-project prototype prepared for review and technical walkthroughs; not production-ready for a live SOC without security hardening, access control, audit logging, and formal review.
